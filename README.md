# Long Range Players

Minecraft Fabric 26.2向けの、遠距離プレイヤー表示MODとNode.js Relayです。通常のプレイヤー表示が届かない場所でも、同じグループの仲間のスキン・姿勢・装備・動作を表示します。

現在の版：**0.9.0**。変更点は[CHANGELOG.md](CHANGELOG.md)を参照してください。

## 導入と使い方

Minecraft 26.2、Java 25、Fabric Loader 0.19.3以上、Fabric API 0.155.2+26.2以上、Cloth Config 26.2.155系列が必要です。Mod Menu・JourneyMap・ReplayMod・Emotecraftは任意です。

1. MODのJARをmodsフォルダーへ入れて起動します。
2. 初回画面で外部送信の説明を読み、仲間と共有するグループコードを入力します。
3. 同意する場合は「はい」を選び、保存します。コードは後から設定することもできます。
4. Minecraftサーバーへ参加すると接続します。同じコード・サーバー・ワールドの利用者が表示されます。

グループコードは**8〜64文字の半角英数字で、英字と数字の両方が必要**です。大文字・小文字を区別します。空欄ではRelayへ接続しません。コードは初回画面、Mod Menu、`/lrp code`から入力できます。自動生成機能はありません。

同意はこのアカウントでの利用に適用します。サーバー参加・ワールド移動・グループコード変更では繰り返し表示しません。アカウントや外部送信の説明が変わった場合は再確認します。「いいえ」やキャンセルでは通信を開始しません。拒否後も設定から説明を確認して再開できます。

| コマンド | 機能 |
| --- | --- |
| `/lrp code` | グループコード入力画面 |
| `/lrp list` | 同じグループの接続者一覧 |
| `/lrp privacy` | 外部送信の説明・同意画面 |
| `/lrp revoke` | 同意撤回・送信停止 |
| `/lrp world` | ワールド識別値の確認 |

通常のプレイヤーが存在する間は第二の体を表示しません。表示開始距離は初期2チャンクで手動変更できます。JourneyMapではスニーク中の表示を隠します。ReplayMod連携では遠距離プレイヤーの表示を録画します。

## 仕組み

```text
Minecraftクライアント
  ├─ WSS → lrp.ebmy.party → HTTP/WebSocket → Relay
  │                                         └─ 同じコード・接続先・ワールドの利用者
  ├─ HTTPS → Mojang公式サービス（アカウント本人確認）
  └─ HTTPS → GitHub（最新版の確認）
```

クライアントの接続先は`wss://lrp.ebmy.party/ws`に固定しています。WSSを使用し、設定から別ドメインへ変更する項目はありません。Relayはグループコードを事前登録せず、コード・Minecraft接続先・ワールド識別値の組み合わせで共有相手を分けます。

アカウント本人確認にはMojangのセッションサービスを使います。Minecraftサーバーへの現在の参加や座標の正しさを証明する仕組みではありません。同一のワールド識別値を通知するプロキシ配下の別バックエンドは区別できないため、その場合は別コードを使用してください。

## 外部へ送信する情報

Relay運営者：**yukugura**。問い合わせ：**配布元のDiscordスレッド**。

| 送信先 | 情報 | 用途 |
| --- | --- | --- |
| Relay | Minecraftプレイヤー名・UUID、接続先アドレスとワールド識別値のハッシュ、ディメンション、グループコード | 利用者と共有グループの識別 |
| Relay | ゲーム内X/Y/Z座標、視線・身体・頭の向き、姿勢、装備アイテムID、腕振り・アイテム使用などの動作、スキン表示部位 | 遠距離表示。通常約10回/秒で更新 |
| Relay | 接続元IP、接続・切断時刻、本人確認・同意の情報 | 接続管理。プロキシ経由では通常プロキシのIPを記録 |
| Mojang公式HTTPS | Minecraftログイントークン、プロフィールID、本人確認用の使い捨てハッシュ | アカウント本人確認。ログイントークンはRelayへ渡さない |
| GitHub API | 最新リリース情報の取得リクエストと接続元IP | 更新通知。プレイヤー名・UUID・座標・グループコードは送らない |

透明化・スペクテイター中は位置・姿勢・装備を送らず、表示取り下げ通知を送ります。Relay管理者は中継情報を処理し、同じコード・サーバー・ワールドの利用者が表示情報を受信します。受信者の録画は送信停止後も残る場合があります。

アクセスログはRelay側だけで管理します。標準保存期間は7日で、運営者が`.env`で変更できます。MCID・UUID・接続元IP・接続時刻などを保存し、座標・装備・グループコード・ログイントークンはアクセスログに保存しません。中継用の最後の姿勢は通常、更新停止から約5秒で破棄します。プロキシ側のログやバックアップはRelayの自動削除とは別管理です。

設定の無効化または`/lrp revoke`で送信を停止できます。

## 更新通知

0.9.0以降は、同意後のサーバー参加時にGitHub Releasesの最新の正式版を起動ごとに一度確認します。Minecraft 26.2対応の新しいJARが公開されている場合、チャットに更新案内を表示します。自動ダウンロード・自動置換は行いません。確認に失敗してもゲームやRelay接続を止めません。

新しい版を案内する際は、このリポジトリのReleasesで`v0.10.0`のようなタグを付け、対応する`long-range-players-0.10.0+mc.26.2.jar`を添付して正式版として公開します。まだReleasesがない場合や同じ版の場合は通知しません。0.8.0以前にはこの通知機能がありません。

## Relayの構築

[RELAY-UPDATE.md](RELAY-UPDATE.md)を参照してください。`.env`の初期設定後は`docker compose up -d`で起動できます。公開URLやNPMの設定は別途管理します。

## ソースと開発

- `mod/src/client/java/dev/codex/longrange/client`：表示・通信・設定・同意・更新通知。
- `relay`：WebSocket中継、本人確認、グループ分離、アクセスログ。
- `mod/src/check/java`・`relay/test`：ローカル自動テスト。

JDK 25・Gradle 9.4で`gradle -p mod build`、Node.js 24でrelayフォルダーにて`npm ci`と`npm test`を実行できます。

0.9.0は通信プロトコル5です。MODとRelayを両方更新してください。ビルドとローカルテストの成功は、Minecraftや各Docker環境での実機確認を意味しません。
